# DeepDiscovery

**A Location–Inference framework for task-level repository understanding in industrial codebases.**

DeepDiscovery takes a natural-language software-engineering task and a (possibly
large, evolving) repository, and recovers the **complete task-relevant
implementation context** needed by a downstream model — not just a few locally
similar fragments. It does this **online**, with **no offline index or graph** to
maintain, so it stays compatible with freshness-sensitive workflows.

This project is a standalone extraction of the "repomap" repository-understanding
component, re-organized around the framework described in the paper
*"DeepDiscovery: A Location–Inference Framework for Task-Level Repository
Understanding in Industrial Codebases."*

## How it works

DeepDiscovery follows a two-stage **Location → Inference** workflow, then
constructs a **metadata-first** structured context package (see the paper, §III,
Algorithm 1).

```
                ┌──────────────────────── Location ────────────────────────┐
  task q  ───▶  │ EnvAnalyze(q,R)  →  AdaptiveCompress(R,B_max)  →  Anchors  │
                └───────────────────────────────────┬──────────────────────┘
                                                     │  Ĥ (task anchors)
                ┌──────────────────────── Inference ─▼──────────────────────┐
                │ multi-relational graph → budget-aware expand → metadata    │
                │  (Priority = Gain/Cost, τ_stop)      first (κ) → Serialize  │
                └───────────────────────────────────┬──────────────────────┘
                                                     ▼
                             structured task-level Context Package
```

| Stage | Module | Paper concept |
|---|---|---|
| Environment-aware analysis | `src/location/envAnalyze.ts` | `c_q` (stack, scope, role priors) |
| Adaptive compression | `src/location/compress.ts` (via the bundled `@ali/repoamap` engine) | `S = AdaptiveCompress(R, B_max)` |
| Rule-guided anchor localization | `src/location/anchorLocalize.ts` + `src/prompts/` | `Score_loc = α·sem + β·sum + γ·rule + δ·prior` |
| Multi-relational graph | `src/inference/projectGraph.ts` (tree-sitter) | `G = (V, A)` |
| Budget-aware expansion | `src/inference/expand.ts` | `Priority(d) = Gain(d)/Cost(d)`, `τ_stop` |
| Second-round refinement | `src/inference/refine.ts` | re-localize on filtered repomap view (dir-tree fallback) |
| Metadata-first context | `src/inference/contextPackage.ts` | promotion score `u(e)` vs `κ`, `Serialize(B)` |
| Result caching | `src/utils/cache.ts` (wired in the orchestrator) | task-keyed context-package cache |
| Orchestrator | `src/core/deepDiscovery.ts` | Algorithm 1 |

The orchestrator preserves the original two-round localization pipeline:
first-round anchor localization on the directory tree → reference-graph expansion
→ **second-round localization on the filtered compressed repomap** (with a
directory-view fallback) → metadata-first context construction, guarded by a
task-keyed cache at both ends.

The rule-template families, artifact-role priors `π_L`, and fusion-weight guidance
(paper §V.E reproducibility artifacts) live in `src/prompts/artifacts.ts`.

## Install

```bash
npm install          # also builds the bundled repomap engine (postinstall)
npm run build        # compile DeepDiscovery itself
```

Requires Node.js ≥ 18. The repository-compression engine (`@ali/repoamap`) is
**vendored** under `vendor/repoamap/` and built locally — no private registry or
`npx` is needed. If the engine build is skipped for any reason, build it manually:

```bash
npm run build:engine   # cd vendor/repoamap && npm install && npm run build
# or build both engine + DeepDiscovery:
npm run build:all
```

If the vendored engine is unavailable at runtime, compression gracefully falls
back to a locally installed `repomix`, then to `npx repomix`.

### The bundled repomap engine

`vendor/repoamap/` contains the actual repomap engine used by the original
system (a repomix-derived packer with tree-sitter compression). DeepDiscovery's
`src/location/compress.ts` invokes its `bin/repoamap.cjs` with
`--compress --style xml`, producing the XML that `src/repomap/xmlParser.ts`
parses into metadata/full-text views. The engine's source is committed; its
`node_modules/` and `lib/` build output are git-ignored and regenerated by
`npm run build:engine`.

## Configuration

Copy `.env.example` to `.env` and set your credentials / parameters:

| Variable | Meaning | Default |
|---|---|---|
| `ANTHROPIC_API_KEY` | API key for the Anthropic-compatible endpoint | — (required) |
| `ANTHROPIC_BASE_URL` | Override for an Anthropic-compatible gateway | Anthropic default |
| `DD_MODEL` | Model id | `claude-opus-4-8` |
| `DD_BUDGET` | `B_max` exploration budget (approx tokens) | `60000` |
| `DD_KAPPA` | `κ` metadata→full-text promotion threshold (0..1) | `0.6` |
| `DD_TAU_STOP` | `τ_stop` expansion stop threshold (0..1) | `0.3` |
| `DD_VERBOSE` | Verbose logging | `false` |
| `DD_CACHE_DIR` | Cache directory | OS cache dir |

## Usage

### CLI

```bash
# built
deepdiscovery --repo ./my-repo --task "Add a retry to the payment flow" --verbose

# from source
npm run dev -- --repo ./my-repo --task "Add a retry to the payment flow"
```

Options: `--budget`, `--kappa`, `--tau-stop`, `--model`, `--output <file>`, `--json`.

### Library

```ts
import { run } from "deepdiscovery"

const pkg = await run({
  repoPath: "./my-repo",
  task: "Add a retry to the payment flow",
})

console.log(pkg.relatedFiles)   // predicted task-relevant file set Ŷ(q)
console.log(pkg.serialized)     // structured context package for a downstream model
```

Inject a custom LLM client (any provider) by implementing `LLMClient` and passing
it via `runDeepDiscovery(options, { llm })`.

## Output: the Context Package

`run()` returns a `ContextPackage`:

- `relatedFiles` — predicted task-relevant files `Ŷ(q)` (the FRR/MR/MP prediction).
- `entities` — selected entities with a `metadata` or `fulltext` view and an
  inclusion `rationale` `ρ_i`.
- `relations` — structural relations traversed during expansion.
- `serialized` — a compact, downstream-consumable rendering of the package.
- `usage` — aggregated token usage and estimated cost.

## Notes & scope

- DeepDiscovery is **recall-oriented**: it favors recovering the complete set of
  implementation / bridge / configuration / test files, which can occasionally
  include a small number of structurally-adjacent non-essential files.
- No offline artifacts are maintained; context is recovered from the current
  repository state on every run.

## Supplementary Material

The `Supplementary_Material/` folder is an **anonymized artifact package** that
supports the verifiability of the main claims in the paper. All materials have
been anonymized and do not reveal the authors' identities or organization.

It contains two folders, plus supporting result/configuration files:

```
Supplementary_Material/
├── SWE-Bench-Verified_logs_trajs/   # end-to-end evaluation evidence on SWE-bench Verified
│   ├── ACoder.20250901_final.json   # official SWE-bench result summary (see numbers below)
│   ├── acoder_diff.jsonl            # predicted patch per instance (500 lines)
│   ├── acoder_logs/                 # per-instance run logs (500 dirs: eval.sh, patch.diff,
│   │                                #   report.json, run_instance.log, test_output.txt)
│   └── acoder_trajs/                # per-instance execution trajectories (500 .md files)
└── AST+Graph_RAG_PROJECT/           # desensitized code for the RAG / GraphRAG / AST+GraphRAG baselines
    ├── AST_Tree_Graph/              # AST parsing → entity/relation extraction → code graph
    ├── rag-python-tools/            # AST / commit / summary data-processing toolset
    ├── graph_search_demo/           # Graph-search retrieval + QA service (Neo4j + vector store)
    └── README.md                    # baseline project documentation and data flow
```

### `SWE-Bench-Verified_logs_trajs/`

Execution trajectories and logs of the **DeepDiscovery-equipped system on
SWE-bench Verified**. This is the publicly reproducible portion of the study:
the evaluation uses the public SWE-bench Verified benchmark under its official
execution and verification protocol.

`ACoder.20250901_final.json` is the official result summary. It records, among
other fields, `total_instances`, `submitted_instances`, `completed_instances`,
`resolved_instances`, and the corresponding id lists. For this run:

| Metric | Value |
|---|---|
| Total instances | 500 |
| Submitted / completed | 500 / 500 |
| **Resolved** | **393** |
| Unresolved | 107 |
| Empty-patch / error | 0 / 0 |
| **Solve Rate** | **78.6%** |

This matches the 78.6% Solve Rate reported for the DeepDiscovery-enhanced system
in the paper. The per-instance `acoder_logs/` and `acoder_trajs/` allow
inspection of individual runs, and `acoder_diff.jsonl` contains the predicted
patch for each instance.

### `AST+Graph_RAG_PROJECT/`

**Desensitized** experimental code for the controlled method-level comparison
baselines — **RAG**, **GraphRAG**, and **AST+GraphRAG** (paper RQ1). It parses
source code into class/method/file entities and their dependency/call/inheritance
relations, builds a code knowledge graph, and applies GraphRAG-style community
detection, LLM community-report generation, embedding, and retrieval to provide
code-understanding / QA. Sample data, keys, internal domains, and business
identifiers have been replaced with placeholders. See its own `README.md` for the
full data flow and per-subproject details.

These materials support inspection of the public end-to-end evaluation on
SWE-bench Verified and **partial** verification of the controlled method-level
comparison.

### Scope and reproducibility statement

As stated in the paper, the SWE-bench Verified evaluation provides publicly
reproducible evidence, whereas the industrial repository-understanding evaluation
should be interpreted as **organization-internal deployment evidence**. Due to
proprietary source code, compliance restrictions, and confidential deployment
assets, the package does **not** include the full implementation of
DeepDiscovery, the industrial codebase, internal task descriptions, gold
relevant-file annotations, relation-extraction specifications, or the full
system-integration details used in the organization-internal evaluation. After
data disclosure is approved, the authors plan to desensitize the complete
experimental and project data and release the desensitized version on GitHub.

> Note: `Supplementary_Material/` is the paper's verification artifact and is
> independent of the runnable DeepDiscovery library/CLI documented above.
